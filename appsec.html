2. Custom WAF rule

Business-specific protection
2

Define the rule

What this rule doesIt blocks only requests to spencerkirn.com/appsec that contain the demonstration marker cf-demo=custom-rule. Ordinary site traffic does not match it.

In Cloudflare, open Security → Security rules → Create rule → Custom rules.

  • Rule name: DEMO — block custom query
  • Action: Block
(http.host eq "spencerkirn.com" and starts_with(http.request.uri.path, "/appsec") and http.request.uri.query contains "cf-demo=custom-rule")

Send the matching request

Run this once before enabling the rule to show an allowed response. Enable the rule in Cloudflare, then run it again to show the same request pattern being blocked.

  4. Open the sampled event and show the action, rule name, URI, source, and Ray ID.

3. Rate limiting

Control abusive request volume
3

Define the rule

What this rule doesIt counts requests from each source IP when the request targets /appsec and contains rate-test=. After the configured threshold is exceeded, Cloudflare blocks additional matching requests for the mitigation period.
  • Name: DEMO — appsec burst
  • Counter characteristic: IP
  • Threshold: 5 requests in 10 seconds
  • Action: Block
  • Mitigation timeout: 10 seconds, if shown
  • Cached assets: Include them
(http.host eq "spencerkirn.com" and starts_with(http.request.uri.path, "/appsec") and http.request.uri.query contains "rate-test=")

Run 12 requests

6. WAF Attack Score

Machine-learning classification
6

Signatures plus machine learning

What Attack Score addsManaged rules identify known exploit signatures. WAF Attack Score independently classifies each request from 1 to 99 based on malicious likelihood. Lower scores indicate greater attack likelihood.
1–20Attack
21–50Likely attack
51–80Likely clean
81–99Clean

Business plans expose cf.waf.score.class. Granular cf.waf.score values and vector-specific scores require Enterprise. Scores appear in Cloudflare analytics and logs; a static page cannot read them from the response.

Example score-based rules

Business — challenge attack-class requests:

(http.host eq "spencerkirn.com" and starts_with(http.request.uri.path, "/appsec") and cf.waf.score.class eq "attack")

Enterprise — challenge granular scores ≤ 20:

(http.host eq "spencerkirn.com" and starts_with(http.request.uri.path, "/appsec") and cf.waf.score le 20)

7. Bot Score

Human and automated traffic
7

Classify automation

What Bot Score doesEnterprise Bot Management assigns each request a score from 1 to 99. A low score indicates likely automation; a high score indicates likely human traffic. Verified bots are identified separately so beneficial automation can be handled differently.
1Automated
2–29Likely automated
30–99Likely human
VerifiedKnown good bot

Granular cf.bot_management.score requires Enterprise Bot Management. Pro and higher can view grouped bot categories under Security → Bots. Cloudflare derives the score from request and behavioral signals; a page cannot force or directly read a score.

Example bot rule

Challenge likely automated traffic on this demo path while excluding verified bots:

(http.host eq "spencerkirn.com" and starts_with(http.request.uri.path, "/appsec") and cf.bot_management.score lt 30 and not cf.bot_management.verified_bot)

Configure the action as Managed Challenge.

Life of a request

How Cloudflare evaluates traffic
Visitor→Cloudflare edge→Security phases→Cache or origin→Response
StageWhat happensIf the request is allowedIf a terminal action occurs
1. ConnectThe visitor resolves the hostname, connects to a nearby Cloudflare data center, and establishes the HTTP/TLS session. Cloudflare assigns request metadata such as a Ray ID.The request enters Cloudflare's request-processing pipeline.Connection-level failures end the request before application controls.
2. HTTP DDoS protectionAlways-on systems evaluate traffic for application-layer denial-of-service patterns.The request continues to customer-configured controls.Mitigated traffic does not proceed to later security phases.
3. Custom rulesCustomer-authored expressions evaluate application context such as host, path, method, headers, IP, geography, and other available fields.The request proceeds to rate limiting.Block or Managed Challenge stops evaluation for that request, so later WAF phases do not see it.
4. Rate limitingCloudflare counts matching requests using configured characteristics such as source IP and compares the rate with the rule threshold.The request proceeds when the counter is below threshold.Requests over threshold receive the configured mitigation until its period expires.
5. Managed WAFEnabled Cloudflare and OWASP managed rulesets inspect request components for known exploit techniques and attack patterns.The request continues when no terminating managed-rule action applies.A blocking or challenge action ends this request before later phases.
6. Super Bot Fight ModeWhen enabled and available, Cloudflare applies the configured handling for automated and verified bot categories.Allowed traffic continues through the remaining request pipeline.The configured challenge or block is returned at the edge.
7. DeliveryAfter security evaluation, Cloudflare can serve a cached response or forward the request to the application origin, depending on configuration and cache state.The application response travels back through Cloudflare to the visitor.A Cloudflare-generated mitigation response is returned instead of the application response.
8. InvestigationRequest and security metadata feed Cloudflare analytics. Security Analytics represents incoming traffic; Security Events represents requests flagged or acted on by security products.Teams can baseline legitimate behavior and improve rules.Teams can investigate the service, action, rule, source, URI, and Ray ID associated with the event.

Key behavior: Cloudflare evaluates these security phases in order. A terminal action prevents later phases from processing that request. The demo therefore uses a distinct query marker for each scenario so the custom rule, rate-limit rule, and managed WAF can be demonstrated independently.
